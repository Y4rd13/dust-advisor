## 3. Item #3 — RotationImminent strategy (real)

### 3.1 Data

Extend `StandardSets.cs` with a second set:

```csharp
public static readonly HashSet<string> RotatingNextYear = new HashSet<string>
{
    // Empty for mid-year. User adds the year-flip rotation sets here ~Jan-Mar.
    // Once filled, RotationImminent surfaces these cards first.
};
```

### 3.2 Algorithm

Restore `Strategy.RotationImminent` behavior in `Advisor.Recommend`. When this strategy is selected:
- Cards from sets in `RotatingNextYear` proceed normally.
- All other cards are skipped (`continue`).

This is analogous to `RefundOnly` but for rotation.

### 3.3 UI

Add `Strategy.RotationImminent` back to the dropdown ItemsSource. Position: between `SafeOnlyUnused` and `MaxDust`.

## 4. Item #4 — Missing-metadata warning

### 4.1 Detection

In `Plugin.RunAsync`, after computing the collection and loading metadata:

```csharp
var metaIds = new HashSet<string>(data.Meta.Select(m => m.CardId));
var missing = collection.Where(c => !metaIds.Contains(c.CardId)).ToList();
```

### 4.2 UI

If `missing.Count > 0`, append a `Warning` entry to the plan via a helper before opening the window:

```csharp
var missingWarning = new Warning("__metadata__",
    $"{missing.Count} cards in your collection have no metadata yet (recently added, not in HearthstoneJSON cache).");
```

This warning shows up in the existing `WarningCountLabel` — no new UI element needed. Already-present mechanism.

## 6. Item #7 — Per-row "why" tooltip

### 6.1 Logic

Add a computed `Why` property to `DustItemRow`:

```csharp
public string Why => BuildWhy();

private string BuildWhy()
{
    if (InDeckCount > 0) return $"Used in {InDeckCount} of your decks. Switch to a non-Unused strategy to consider dusting.";
    if (Flag == "REFUND")  return $"In refund window: full craft cost recoverable for limited time.";
    if (Flag == "STANDARD") return $"Standard-legal: may still be valuable in current meta. SafeOnly skips by default.";
    if (Flag == "WILD") return $"Wild-only: rotated out of Standard. Lower opportunity cost.";
    return "";
}
```

### 6.2 UI

Add a `ToolTip` to the Flag column:

```xml
<DataGridTextColumn Header="Flag" Binding="{Binding Flag}" Width="100">
  <DataGridTextColumn.ElementStyle>
    <Style TargetType="TextBlock">
      <Setter Property="ToolTip" Value="{Binding Why}"/>
    </Style>
  </DataGridTextColumn.ElementStyle>
</DataGridTextColumn>
```

## 7. Item #9 — Confirm bar perf refactor

### 7.1 Replace `CompositionTarget.Rendering`

Current code:
```csharp
CompositionTarget.Rendering += (s, e) => UpdateConfirmBar();
```

This fires ~60 fps regardless of selection changes.

### 7.2 Replacement: PropertyChanged subscription

When building the row list in `Render`, subscribe to each row's `PropertyChanged`:

```csharp
foreach (var r in newRows)
{
    r.PropertyChanged += (s, e) =>
    {
        if (e.PropertyName == nameof(DustItemRow.IsSelected)) UpdateConfirmBar();
    };
}
```

Unsubscribe old rows when replacing ItemsSource (optional for personal tool — let GC clean up since they're throwaway).

Remove the `CompositionTarget.Rendering` line.

## 8. Item #10 — Meta tier (curated)

### 8.1 Data

New curated file `data/meta_tiers.json`:

```json
[
  { "cardId": "EX1_001", "tier": "S" },
  { "cardId": "EX1_002", "tier": "A" }
]
```

Tiers: `S`, `A`, `B`, `C`, `?` (default unknown). User updates this monthly from Vicious Syndicate / HSReplay reports.

### 8.2 Repository

`src/DustAdvisor.Data/MetaTierRepository.cs`:

```csharp
public sealed class MetaTierRepository
{
    public IReadOnlyDictionary<string, string> Load(string path) { ... }
}
```

Returns dict mapping cardId → tier ("S", "A", ...).

### 8.3 Algorithm + UI

- `DataSnapshot.MetaTiers` (new property, default empty).
- `DataLoader.LoadAsync` reads it from `data/meta_tiers.json` via `PluginPaths.MetaTiersFile`.
- `DustItem.MetaTier` (string, default `"?"`).
- `Advisor.Recommend` populates from `inputs.MetaTiers` dict (new field on AdvisorInputs).
- UI: new column `Tier` between `Dust` and `In Decks`, width 40. Just displays the letter.
- For v1.3, the algorithm doesn't change based on tier — it's just exposed for the user to see. A future strategy could use it.

## 9. Item #11 — Win-rate per card

### 9.1 Source

`Hearthstone_Deck_Tracker.Stats.DeckStatsList.Instance.DeckStats` — list of `DeckStats` objects, each with a `Games` list of `GameStats` having `Result` (Win/Loss/etc.) and `PlayerDeckId` (the deck the game was played with).

For each deck, compute `wins / total`. For each card, find decks containing it (we already have `deckUsage` from v1.2 but it maps to count of decks, not deck IDs).

### 9.2 Refactor `deckUsage`

Change `BuildDeckUsage()` return type from `Dictionary<string, int>` to `Dictionary<string, List<Guid>>` (cardId → list of deck IDs that contain it). The existing `InDeckCount` becomes `deckIds.Count`.

Add a parallel `Dictionary<Guid, (int wins, int total)>` for deck stats.

For each card:
- Find its `deckIds`.
- Sum wins and totals across those decks.
- If `total >= 20`, expose `WinRate = wins / total`. Else `null`.

### 9.3 Algorithm + UI

- `DustItem.WinRate: double?` (null if not enough games).
- `DustItemRow.WinRateDisplay` → "57%" or "" if null.
- New column `WR%` after `Tier`, width 50.

## 10. Item #12 — Class filters

### 10.1 Data

`HearthstoneJsonCardDto` already has the JSON field `cardClass` (we just don't currently parse it). Add it.

`CardMeta` extends to include `Class: string` (e.g., `"DRUID"`, `"NEUTRAL"`).

`HearthstoneJsonClient` maps `dto.CardClass` to `meta.Class`.

### 10.2 Pipeline

`DustItem.Class: string` (new field). Plumbed from `meta.Class`.

### 10.3 UI

New row of filter checkboxes (or compact dropdown) below the existing filter row. 11 classes: Druid, Hunter, Mage, Paladin, Priest, Rogue, Shaman, Warlock, Warrior, Demon Hunter, Death Knight, Neutral. All checked by default.

Compact UI: ToggleButtons in a horizontal stack with class icons or just initials.

For simplicity in v1.3, use a `ComboBox` with class checkboxes inside (multi-select dropdown style is awkward in WPF — use a simple ListBox in a Popup, or just add a row of 12 small ToggleButtons).

**Decision: 12 small CheckBox elements in a wrapping panel**, all checked by default. Filter line in `ApplyFilters`: `if (!selectedClasses.Contains(item.Class)) continue;`.

## 12. Risks

| Risk | Mitigation |
|---|---|
| Class filters double the UI complexity | Use compact multi-checkbox row. Worst case: drop to a single "exclude Druid/Hunter/etc" dropdown. |
| Win-rate noisy with low game count | 20-game threshold. Display blank when below. |
| `RotatingNextYear` is empty mid-year | RotationImminent returns empty plan with a clear warning explaining the state. |
| Meta tier requires manual updates | Document; user can leave the file empty. |
| `DeckStatsList` API may differ in HDT | try/catch fallback like `BuildDeckUsage`. |
| Tooltip on DataGridCell may not bind through ElementStyle in all cases | Test; fallback is a `DataGridRow.ToolTip` per-row binding. |
