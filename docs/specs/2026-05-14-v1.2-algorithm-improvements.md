# Dust Advisor v1.2 — Algorithm Improvements

**Status:** Approved
**Date:** 2026-05-14
**Scope:** Personal/local. Builds on v1.1.

## 1. Goal

Four targeted improvements to the dust advisor algorithm and UI:

- **A. Deck cross-reference** — don't recommend cards the user is actively playing.
- **B. Live name search** — type-to-filter the grid.
- **C. Cache expiration** — refresh HearthstoneJSON if older than 7 days.
- **D. Locale fix** — show card names in the user's Hearthstone language.

Each is independent. Each ships as its own commit so we can stop at any point.

## 2. Non-Goals

- HSReplay tier integration, win-rate per card, class-based agro filtering (out of scope; v1.3 candidates).
- Auto-detecting refund-window cards from patch notes RSS.
- Re-importing decks live while the window is open (snapshot at window-open is enough).

## 3. Package A — Deck cross-reference

### A.1 Data extraction

At window open (in `Plugin.RunAsync`), read `Hearthstone_Deck_Tracker.DeckList.Instance.Decks`. For each deck where `IsArenaDeck == false` and `Archived == false`, iterate `deck.GetSelectedDeckVersion().Cards` and accumulate `(card.Id, count)` into a `Dictionary<string, int>` named `deckUsage`. The dict maps cardId → number of distinct decks containing it (not total copies across decks).

Pass `deckUsage` into `AdvisorInputs` as a new read-only property.

### A.2 Algorithm

Extend `AdvisorInputs` with `IReadOnlyDictionary<string, int> DeckUsage` (default empty).

In `Advisor.Recommend`, after computing `meta` for a card, also fetch its usage count. Pass it to `DustItem` as a new property `InDeckCount: int`.

Add a new strategy: `Strategy.SafeOnlyUnused`. In the foreach loop, if `Strategy == SafeOnlyUnused && InDeckCount > 0`, `continue`. Standard-legal handling unchanged (already produces a warning).

### A.3 UI

- New `DataGridTextColumn Header="In Decks" Binding="{Binding InDeckCount}" Width="60"` placed between the existing `Dust` column and `Flag` column.
- Existing `Flag` column: if `InDeckCount > 0`, override the flag to `IN-DECK` (red foreground in `DustItemRow.Flag` computation). Precedence: `IN-DECK > REFUND > STANDARD > WILD`.
- Add `Strategy.SafeOnlyUnused` to the strategy dropdown items list.

### A.4 Edge cases

- Cards in decks the user has but hasn't played in a year: still counted. The user can archive those decks in HDT if they want them excluded.
- Archived decks excluded by design.
- Arena decks excluded (transient drafts, not collection commitments).

## 4. Package B — Live name search

### B.1 UI

In `DustAdvisorWindow.xaml`, in the filter row (`Grid.Row="1"`), append:

```xml
<TextBlock Text="🔍" VerticalAlignment="Center" Margin="16,0,4,0"/>
<TextBox x:Name="SearchBox" Width="160" VerticalAlignment="Center"/>
```

Place after `AutoAdvanceBox`.

### B.2 Behavior

`SearchBox.TextChanged` → `Render(_plan)`. Inside `ApplyFilters`, after the existing rarity/format/premium filters, add:

```csharp
if (!string.IsNullOrEmpty(searchText)
    && (i.CardName == null || i.CardName.IndexOf(searchText, StringComparison.OrdinalIgnoreCase) < 0))
    continue;
```

Search is substring, case-insensitive, name only (not text/flavor). Updates on every keystroke; no debounce needed for a few-thousand-row grid.

## 5. Package C — Cache expiration

### C.1 Behavior

`CachingHttpFetcher` currently always tries `_inner.GetAsync` first, falling back to cache only on exception. Problem: when the inner is reachable but the cached file is fresh, we still hit the network needlessly.

New behavior:
- If cached file exists and `File.GetLastWriteTimeUtc(path) > UtcNow - MaxAge`, return cached bytes immediately (no network call).
- Otherwise, try `_inner.GetAsync`. On success, write cache, return.
- On failure, return stale cache if it exists. Else throw (existing behavior).

`MaxAge = TimeSpan.FromDays(7)`. Constant in the class for now; if we want it configurable later, expose a constructor parameter.

### C.2 Implementation

Add a freshness check at the top of `GetAsync`. Implement the priority: fresh-cache → network → stale-cache → throw.

## 6. Package D — Locale fix

### D.1 Detection

HDT exposes `Hearthstone_Deck_Tracker.Config.Instance.SelectedLanguage`. This is a string like `"esMX"`, `"enUS"`, `"frFR"`. Read it at window open in `Plugin.RunAsync`. Fallback to `"enUS"` if null or empty.

### D.2 Plumb-through

Pass the locale string to `loader.LoadAsync(locale: hdtLocale, ...)`. HearthstoneJSON supports 15 locales using the same codes. CardArtCache currently hardcodes `enUS` in its URL — also accept a `locale` constructor parameter.

### D.3 Card art locale

`CardArtCache(IBinaryFetcher, string cacheDir, string locale = "enUS")`. The URL becomes `https://art.hearthstonejson.com/v1/render/latest/{locale}/{size}x/{cardId}.png`. Update `Plugin.RunAsync` to pass the same locale.

## 7. Risks / Tradeoffs

| Risk | Mitigation |
|---|---|
| `DeckList.Instance.Decks` API may not be public or stable | Test at compile-time; fall back to empty deckUsage if reflection fails |
| Cards in decks the user no longer plays inflate "InDeckCount" | User can archive decks in HDT; doc this in the spec |
| Stale cache (>7d) leads to outdated rotation flags | Acceptable; user can delete `cache/*.json` to force fresh fetch |
| HDT locale code might not match HearthstoneJSON's exactly | Whitelist the 15 supported codes; fall back to `enUS` for any unknown |
| Card art for an unrecognized locale 404s | `CardArtCache` already returns null on fetch failure; UI shows no art |

## 8. Implementation Order

1. Package C (cache expiration) — pure refactor of existing class, smallest risk.
2. Package D (locale fix) — plumb-through, low risk.
3. Package B (search box) — UI addition, no algorithm change.
4. Package A (deck cross-reference) — biggest change, last.

Each package = 1-2 commits. Total: ~6-8 commits. After Package A, tag `v1.2-personal`.
